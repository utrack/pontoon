# RFC: Total Description

## Overview

This RFC outlines the technical implementation approach for the Total Description feature, which merges runtime OpenAPI definitions with documentation YAML to create comprehensive API documentation.

## Related Documents

- Feature Description: [002-total-description.md](/doc/features/002-total-description.md)

## Technical Design

### Core Components

1. Documentation Merger
   - Input:
     - Runtime OpenAPI definitions generated by `httpinmeditate`
     - Documentation YAML from `cmd/docgen`
   - Output: Merged OpenAPI 3.1 specification
   - Implementation:
     - Use `github.com/pb33f/libopenapi` for OpenAPI schema handling
     - Create a new package `docmerge` for merging logic
     - Implement merge strategies for each OpenAPI component type

2. Documentation Enhancement Pipeline
   - Stage 1: Parse input documents and generate OpenAPI schema
     - Parse runtime OpenAPI from `httpinmeditate`
     - Parse documentation YAML from `docgen`
     - Validate both inputs
   - Stage 2: Merge schemas and metadata
     - Match services and types between runtime and docs
     - Merge documentation comments into OpenAPI descriptions
     - Preserve all OpenAPI validation rules and HTTP bindings
   - Stage 3: Apply documentation enhancements
     - Process Go-style documentation comments
       - Extract deprecation status from last paragraph's first word
       - Mark corresponding OpenAPI elements (fields/handlers/structs) as deprecated
     - Add service-level documentation
     - Enhance type and field descriptions
   - Stage 4: Output merged documentation
     - Generate final OpenAPI 3.1 spec
     - Ensure all `httpin` annotations are preserved

### Comment Processing Rules

The pipeline processes Go-style documentation comments to extract metadata:

> Note: Currently only deprecation status is extracted from comments. More metadata types (examples, validation rules, etc.) will be added in future iterations.

1. Deprecation
   ```go
   // UserProfile represents a user in the system.
   //
   // Contains personal information and preferences.
   //
   // Deprecated: use ExtendedProfile instead.
   type UserProfile struct {
   ```
   This comment will mark the `UserProfile` type as deprecated in OpenAPI.

2. Field Documentation
   ```go
   type UserProfile struct {
       // Name is the user's full name.
       //
       // Deprecated: use FirstName and LastName instead.
       Name string
   }
   ```
   The field `Name` will be marked as deprecated in OpenAPI.

3. Handler Documentation
   ```go
   // GetUser returns user profile by ID.
   //
   // Deprecated: use GetUserV2 instead.
   func (h *Handler) GetUser(r *http.Request) (*UserProfile, error)
   ```
   The endpoint will be marked as deprecated in OpenAPI.

### Documentation YAML Structure

```yaml
checksum: string  # File checksum for validation
services:         # Service definitions
  ServiceName:    # Name of the service
    id: string    # Fully qualified service ID
    type: string  # Type of the definition (service)
    pkg_path: string # Package import path
    type_name: string # Type name in the package
    file: string  # Source file path
    line: int    # Line number in source
    comment: string # Service documentation
    methods:     # Service methods
      MethodName:
        file: string
        line: int
        comment: string
        input_type: string  # Optional
        output_type: string # Optional
        formed_error: bool  # Optional
types:           # Type definitions
  TypeID:        # Fully qualified type ID
    package: string
    name: string
    file: string
    line: int
    is_struct: bool
    fields:      # Optional, for structs
      - name: string
        type: string
```

### Implementation Details

#### Documentation Merger

```go
package docmerge

// MergeOptions configures the merge behavior

type mergeOptions struct {
    preserveExisting bool // preserve existing documentation in the OpenAPI Document
    strictValidation bool // error out on any potential issue during merge
}

type Option func(*mergeOptions)

// WithPreserveExisting configures whether to keep existing documentation in the OpenAPI Document.
// If true, existing documentation will not be overwritten by the YAML documentation.
func WithPreserveExisting(preserve bool) Option {
    return func(o *mergeOptions) {
        o.preserveExisting = preserve
    }
}

// WithStrictValidation enables strict validation during merge.
// If true, any potential issue (missing docs, type mismatches etc) will result in an error.
func WithStrictValidation(strict bool) Option {
    return func(o *mergeOptions) {
        o.strictValidation = strict
    }
}

// Merge merges the documentation into the OpenAPI schema
func Merge(runtime *libopenapi.Document, docs *docgen.Documentation, opts ...Option) (*libopenapi.Document, error)
```

#### Enhancement Pipeline

```go
package docmerge

// Pipeline processes documentation through multiple stages
type Pipeline struct {
    stages []Stage
}

// Stage represents a single documentation processing stage
type Stage interface {
    Process(doc *libopenapi.Document) error
}

// ConflictTracker tracks documentation conflicts
type ConflictTracker struct {
    Conflicts []Conflict
}
```
