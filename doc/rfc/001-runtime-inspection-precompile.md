# RFC: Runtime Inspection - Pre-compile Comment Extraction

## Related Feature
[Runtime Inspection Feature](/doc/features/001-runtime-inspection.md)

## Overview
This RFC describes the implementation of the pre-compile comment extraction component of the Runtime Inspection feature. This component is responsible for extracting and storing documentation from Go source code comments during the build process.

## Technical Approach

### 1. Comment Extraction Tool

#### Design
- Create a new package `docgen` for documentation generation tools
- Implement a Go AST walker to extract comments from:
  - Service structs (implementing `sdesc.Service`)
  - Handler methods
  - Input/output structs and their fields
  - Related type definitions

#### Identifier Generation
```go
type DocID struct {
    PkgPath    string   // Full package import path
    TypeName   string   // Type name (for services/structs)
    MethodName string   // Method name (for handlers)
    FieldPath  []string // Field path for nested structs
    FilePath   string   // File path relative to module root
    Line       int      // Line number in source
}

func (id DocID) Hash() string {
    // Generate stable hash for runtime lookup
    h := sha256.New()
    h.Write([]byte(fmt.Sprintf("%s/%s.%s/%s:%d",
        id.PkgPath,
        id.TypeName,
        id.MethodName,
        strings.Join(id.FieldPath, "."),
        id.Line,
    )))
    return fmt.Sprintf("%x", h.Sum(nil)[:8]) // First 8 bytes is enough
}
```

#### Comment Processing
```go
type DocComment struct {
    ID          string   // Stable hash for runtime lookup
    Path        string   // Full path to the type/field
    Comment     string   // Raw comment text
    SourceFile  string   // Source file path
    Line        int      // Line number in source
    Type        string   // Comment type: "service", "handler", "struct", "field"
    Identifier  DocID    // Full identifier information
}

type ServiceDoc struct {
    Name     string       // Service name
    Package  string       // Package path
    Comments []DocComment // All related comments
}
```

### 2. TOML Generation

#### Format
```toml
# Generated by pontoon docgen - DO NOT EDIT
checksum = "sha256-hash-of-source-files"

[UserService]
id = "a1b2c3d4"  # Stable hash for runtime lookup
type = "service"
comment = """
UserService handles user-related operations.
"""
pkg_path = "github.com/example/myapp/services"
type_name = "UserService"
file = "services/user.go"
line = 42

[UserService.CreateUser]
id = "e5f6g7h8"
type = "handler"
comment = "Creates a new user in the system"
method_name = "CreateUser"
file = "services/user.go"
line = 50

[UserService.CreateUser.Input]
id = "i9j0k1l2"
type = "struct"
comment = "Input parameters for user creation"
field_path = ["Input"]
file = "services/user.go"
line = 60

[UserService.CreateUser.Input.Name]
id = "m3n4o5p6"
type = "field"
comment = "User's full name"
field_path = ["Input", "Name"]
file = "services/user.go"
line = 65
```

#### Implementation
- Generate one TOML file per service
- Store in `internal/gen/docs/{service-name}_doc.go` as string constants
- Include source file checksum for regeneration detection
- Format TOML for git-friendly diffs (stable field ordering, consistent indentation)

### 3. Build Integration

#### Go Generate Command
```go
//go:generate go run github.com/utrack/pontoon/cmd/docgen -package=internal/gen/docs
```

#### Implementation
1. Create `cmd/docgen` tool:
```go
package main

func main() {
    // Parse flags
    pkg := flag.String("package", "", "Output package path")
    flag.Parse()

    // Find all services
    services, err := findServices()
    if err != nil { ... }

    // Extract docs
    docs, err := extractDocs(services)
    if err != nil { ... }

    // Generate TOML
    for _, doc := range docs {
        toml := generateTOML(doc)
        writeToFile(toml, doc.Name)
    }
}
```

2. Add build tag to exclude generated files from documentation extraction:
```go
//go:build !docgen
```

## Error Handling
1. **Parse Errors**
   - Log detailed error with file and line number
   - Continue processing other files
   - Exit with non-zero code after processing all files

2. **Generation Errors**
   - Fail immediately with clear error message
   - Remove any partially generated files

## Testing Strategy
1. **Unit Tests**
   - Test comment extraction from various Go constructs
   - Verify TOML generation format
   - Test checksum generation and verification

2. **Integration Tests**
   - Test full generation pipeline with example services
   - Verify generated files match expected output
   - Test regeneration detection

3. **Test Fixtures**
   - Create comprehensive test services covering all comment types
   - Include edge cases (multi-line comments, special characters)

## Backward Compatibility
- Generated files use build tags to prevent recursive processing
- No changes to existing code structure required
- Generation tool fails if output directory doesn't exist (won't create unexpected directories)

## Implementation Steps
1. Create basic docgen command structure
2. Implement AST walker for comment extraction
3. Add TOML generation with checksums
4. Implement build integration
5. Add comprehensive tests
6. Add documentation and examples

## Future Considerations
1. **Performance Optimization**
   - Parallel processing for large codebases
   - Incremental generation based on file changes

2. **Integration with Runtime Component**
   - Design clean interface for runtime component to read TOML data
   - Consider adding metadata for runtime validation

## Dependencies
- Go 1.21+ (for consistent hash generation across platforms)
- Standard library only (no external dependencies required)

## Impact Analysis
1. **Build Process**
   - Adds a new go:generate step
   - No impact on existing build steps
   - Minimal impact on build time (runs only when source changes)

2. **Runtime**
   - No runtime impact (pre-compile only)
   - Generated files are excluded from runtime binary if unused

3. **Development**
   - Developers need to run `go generate` after comment changes
   - Clear error messages guide developers to fix documentation issues
   - IDE integration possible through standard go:generate support

## Security Considerations
- No security impact (documentation generation only)
- No external network access required
- No sensitive information processing

## Migration Plan
1. Initial rollout:
   - Add docgen tool
   - Generate documentation for new services
   - Add to CI pipeline

2. Existing services:
   - Generate documentation for existing services
   - Review and clean up existing comments
   - No breaking changes required

## Success Metrics
1. **Code Quality**
   - All new services have complete documentation
   - No documentation conflicts reported
   - Clean git diffs for documentation changes

2. **Developer Experience**
   - Clear error messages
   - Fast generation time
   - Minimal manual intervention needed
